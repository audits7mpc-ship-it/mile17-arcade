Putting the Table Arcade live

Everything runs on one free Cloudflare account. No terminal, no installing anything — every step below is clicking around a website. Budget about half an hour the first time.

0What you have

FileWhat it is
index.htmlThe arcade itself. This is what guests see. Already named correctly — don't rename it.
mile17-pass-worker.jsThe pass server. Enforces one go per device per day.
schema.sqlOne block of SQL you paste in once to create the database table.
qr-sheet.htmlMakes the printable QR code for the benches.
preview-build.htmlFor you, not for guests. Every lock off so you can see any screen on demand.

Do these in order

The page needs to know the server's address, and the server needs to know the page's. Doing step 4 before step 2 means going back and redoing it.

1Make a Cloudflare account

  1. Go to dash.cloudflare.com/sign-up
  2. Email and a password. No card, no domain needed.
  3. Verify the email they send you.

2Publish the page

  1. The folder 1-arcade is already made for you, with index.html inside.
  2. Put index.html inside it. Nothing else in that folder.
  3. In Cloudflare, left sidebar → Compute (Workers & Pages)
  4. Create → the Pages tab → Upload assets
  5. Project name: mile17-arcade → Create project
  6. Drag the 1-arcade folder onto the upload box → Deploy site

You now have an address like https://mile17-arcade.pages.dev. Copy it and keep it somewhere — you need it twice more.

Check it

Open that address on your phone. The film should play and the arcade should appear. The device lock isn't on yet — that's the next three steps.

3Create the database

  1. Left sidebar → Storage & Databases → D1 SQL Database
  2. Create Database, name it mile17 → Create
  3. Open it → the Console tab
  4. Paste the block below and hit Execute
CREATE TABLE IF NOT EXISTS passes ( id TEXT PRIMARY KEY, day TEXT NOT NULL, game TEXT NOT NULL, tries INTEGER NOT NULL, spent INTEGER NOT NULL DEFAULT 0, win_on INTEGER, won INTEGER NOT NULL DEFAULT 0, code TEXT, intro INTEGER NOT NULL DEFAULT 0, created TEXT NOT NULL ); CREATE INDEX IF NOT EXISTS passes_day ON passes(day);

It should say the statements ran. You won't see any rows yet — that's correct, guests make them.

4Create the pass server

  1. Compute (Workers & Pages) → Create → Workers tab → Start with Hello World
  2. Name it mile17-pass → Deploy
  3. Edit code. Click in the editor, select everything (Ctrl+A / Cmd+A), delete it.
  4. Open mile17-pass-worker.js in Notepad or TextEdit, select all, copy, and paste into the empty editor.
  5. Deploy again, then go back to the worker's Settings.

Connect the database to it

  1. Bindings → Add → D1 database
  2. Variable name: DB — exactly those two letters, capitals
  3. Database: mile17 → Deploy

Add two settings

Variables and Secrets → Add, twice:

NameValue
ALLOW_ORIGIN Your Pages address from step 2, e.g. https://mile17-arcade.pages.dev
No slash on the end. This must match exactly or the phone will be refused.
RESET_KEY Any password you invent. Without it, anyone who finds the worker's URL could wipe guests' passes.

Deploy. At the top of the worker page is its address, something like https://mile17-pass.yourname.workers.dev. Copy that too.

5Join the two together

  1. Open index.html in Notepad (Windows) or TextEdit (Mac). Not Word — Word will wreck the file.
  2. Press Ctrl+F / Cmd+F and search for var PASS_API. It's near the top, around line 635.
  3. You'll see this:
var PASS_API = '';

Put your worker address between the quotes, so it reads:

var PASS_API = 'https://mile17-pass.yourname.workers.dev';

Keep the quotes and the semicolon. No slash at the end. Save the file.

  1. Back in Cloudflare → your mile17-arcade Pages project → Create new deployment → drag the 1-arcade folder in again.

6Test before you print anything

This is the step people skip and regret. Reprinting twenty-four QR codes is not fun.

  • Open the page on your phone. The film plays, then Play & Win.
  • It deals you one game — Jackpot or the wheel, never both.
  • Play it out. The reward screen or the better-luck screen appears, then Play more games underneath with ten games and neither prize game in the list.
  • Reload the page. No film, no second go.
  • Now the real test: open the same address in a different browser on that same phone. If you scanned from WhatsApp, open it in Chrome. It should still say your go is spent.

If the different browser gives you a fresh go

The worker isn't connected. Ninety-nine times out of a hundred it's one of two things: PASS_API didn't save, or ALLOW_ORIGIN doesn't match your Pages address character for character. Check both.

7Print the bench codes

  1. Open qr-sheet.html by double-clicking it — it opens in your browser.
  2. Paste your Pages address and, if you like, a line to print under the code
  3. Make the sheet → Print

Each code carries its own table number, so when a reward comes up your steward can see which bench it came from. The codes are printed at the highest error-correction level, so a thumbprint or a tea ring won't stop them scanning.

8Day to day

Changing something later

Edit index.html, then Pages project → Create new deployment → drag the folder. The QR codes never change, so you never reprint.

Turning games on and off

Add ?admin=1 to your address, tap the gear, tick what you want, copy the link it gives you. That link is what goes behind the QR code.

Showing someone how it works

Use preview-build.html — open it from your computer. Bar along the bottom lets you force a win, force a miss, and deal either game. It never touches the server and its rewards are stamped PREVIEW, so it can't be used to claim anything.

10When something's wrong

What you seeWhat it usually is
A list of files instead of the arcadeThe file isn't named index.html, or it wasn't inside a folder when you dragged it.
Page loads but looks like plain textThe file was saved by Word. Re-download it and use Notepad or TextEdit.
A different browser gets a fresh goPASS_API or ALLOW_ORIGIN. See step 6.
Everything works but no film on your phoneYou already used today's pass. That's correct behaviour — it comes back at midnight IST.
Worker page says "D1 not bound as DB"The binding variable name isn't exactly DB. Capitals matter.
A guest says their go was already spent and they never playedTwo identical phone models can produce the same fingerprint. Rare, but real — tell me and I'll fold the table number into the key.

One account, three free Cloudflare products: Pages for the arcade, Workers for the pass server, D1 for its database. Nothing else is involved and nothing leaves Cloudflare.

The only personal thing stored is a fingerprint hash — screen size, graphics chip, core count, timezone. It cannot be turned back into a phone number, a name, or a person, and rows older than two days delete themselves.
